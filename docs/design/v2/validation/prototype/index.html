No participant session has used these storyboards. Nothing here is a finding.

What these test, and what they cannot

  • They test vocabulary and flow: whether people find things, read the labels as meant, and recover from capture and sync edge cases.
  • They do not prove the final Avalonia application is accessible. Browser semantics are not UI Automation, and Narrator on a web page is not Narrator on a native window.
  • They do not show visual fidelity. The palette exists only so contrast is realistic.
  • They use one shared sample content file, so both variants show identical names and numbers. All of it is illustrative.
  • They make no network request, read no user or game file, and press no game key. They load only bundled sample assets; the moderator simulates every screenshot.

Running a session

  1. Open from the repository docs/ tree, or serve the repository root. Do not copy only this prototype/ folder: its journey, Safety and data-methodology links are part of the study material.
  2. Open Moderator controls at the bottom of a storyboard, choose Reset session, then a journey start point.
  3. For the paired-tablet journey on a real tablet, copy the complete docs/ tree to the device or serve the repository root on the local network, and open the #/tablet address.
  4. Prefer the participant's own operating-system settings for high contrast, text size and reduced motion. The moderator toggles are a fallback.

The scripts, tasks and expected answers are in journeys.md. The research plan is research-plan.md. Before distribution, run node docs/design/v2/validation/prototype/link-audit.mjs and node docs/design/v2/validation/prototype/storyboard-audit.mjs from the repository root. The first audits the canonical docs/ bundle; the second uses local Chromium to crawl both rendered variants.
