# Windows platform-boundary adversarial review

## Scope and method

This is the Windows lane of #317, conducted as a source-grounded static review at
`d59d136` on 2026-09-14. It covers P/Invoke, process and window discovery, visible-pixel
GDI capture, native OCR, watched paths, shell placement, DPAPI storage, packaging, install,
and update privilege boundaries. No build, test, debugger, Windows VM, container, capture, or
EFT process was run for this review; therefore every evidence statement below is **Reviewed**
unless it explicitly names an existing test as coverage rather than a test run.

Severity uses `docs/security/METHODOLOGY.md`. “Same-user attacker” means a process already able
to modify that Windows user’s writable profile or install directories; it is not treated as a
remote attacker. Owners are deliberately role/issue owners where the repository names no person
for the work, so an unassigned issue owner is visible rather than invented.

## Boundary proof

The reviewed source remains external and read-only toward EFT. `WindowsGameWindowLocator` uses
ordinary process metadata and top-level window handles; `GdiScreenCaptureService` uses
`GetWindowDC`/`BitBlt` to copy visible desktop pixels only. Neither opens an EFT process handle
nor names a memory-read/write, remote-thread, hook, renderer, packet-capture, or input-synthesis
API. `MainWindow` handles input only while the companion is focused, and the reviewed App source
contains no topmost/layered/click-through/reparenting implementation. Thus visible-pixel capture
and ordinary window discovery are permitted observations; they are not process-memory access,
generated game input, or an in-game overlay. `scripts/audit-safety.sh` supplies a reviewed,
partial lexical ratchet for those three immutable boundaries, including its forbidden APIs and
the two statement-shaped overlay checks.

## Review conclusion

The immutable anti-cheat boundaries hold in the reviewed implementation: there is no observed EFT
memory access, generated game input, or in-game overlay. The allowed visible-pixel and window
discovery path nevertheless has integrity and privacy weaknesses around identity revalidation,
integer bounds, and reparse/TOCTOU handling. Two High findings remain open: uncontained watched
paths (WIN-005) and native/update supply-chain trust (WIN-008 and WIN-012); they require named
owners and mitigation rather than a silent release acceptance.
